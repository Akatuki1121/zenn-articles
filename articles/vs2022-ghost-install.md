2026年5月にVisual Studio 2022と2026を同じパソコンへ同居させた日、Hello Worldすらビルドできなくなりました。ctype.hが開けない、stdio.hが無い、float.hが見つからない。E1696とE0282が画面いっぱいに出て、最小構成のコンソールアプリでも同じ結果でした。標準ヘッダが丸ごと見えなくなっていたのです。

この記事はその環境を直すまでに起きたことの記録です。結論を先に書くと、正体はWindows SDKの「ゴーストインストール」でした。インストーラーは成功したと報告するのに、肝心のファイルは一つも置かれていない状態です。同じ症状で止まっている人の役に立てばと思い、残してあった作業記録をもとに書き直したものです。

## まず疑ったのはコンポーネントの脱落だった

最初はVS2026 Previewのインストールや累積アップデートのどこかで、Windows Universal CRT SDKなどの部品が外れたのだろうと考えました。実際、当時の記録にもそう推定してあります。

定石は一通り試しました。Visual Studioの修復とSDKの再インストール、Visual Studio InstallerからのSDKの追加と削除の繰り返し。どれも完了まで進むのにctype.hの欠損はそのままでした。壊れた状態のままではVisual Studio Installerからのアンインストール自体も部分的に失敗し、強制削除の道具も相性が悪くて断念しました。

ここで見方を変えました。インストーラーの報告ではなく、実物のフォルダを見ることにしたのです。Windows SDKのIncludeフォルダを確認すると、入っているはずのヘッダが物理的に存在しなかったのです。成功したはずのインストールが、ファイルを一つも置いていなかったのです。

## ゴーストインストールの仕組み

後の診断で固まった結論はこういうものでした。VS2026 Previewなどが残したSDK AddOnが、MSIのデータベースとレジストリの中に異常なバージョン値を持っていました。167837696という、エポック秒のような巨大な数値です。その値があると「既に最新版が入っている」ように見えるため正規のインストーラーは自分の仕事を終えたつもりになり、IncludeもLibもbinも展開せずに成功を報告します。

公式の単体インストーラーであるwinsdksetup.exeを直接実行しても結果は同じです。成功と表示されるのに、Includeフォルダは生成されません。レジストリの上では存在しているのにディスクの上には存在しない。この幽霊のような状態が、ゴーストインストールと呼ぶのが一番しっくりくる姿でした。

## 全削除と入れ直し、それでも直らなかった

一度環境を丸ごと消して入れ直すことにしました。プロセスを止めてインストーラーで本体を外し、残ったフォルダと設定とキャッシュとレジストリを順に消していく作業です。このときPackage Cacheは丸ごとではなくVisual Studio関連のサブフォルダだけに絞って、レジストリはバックアップを取ってから消しました。VS2026 Previewの残骸だった「C:\Program Files\Microsoft Visual Studio\18\」も、この段階で消しています。

入れ直しではC++によるデスクトップ開発に加えて、MSVC v143とWindows 11 SDKとWindows Universal CRT SDKを個別コンポーネントとして明示的に選びました。ところが途中でもう一つ、今度はfloat.hが見つからないというC1083が出たのです。Visual Studio Installer経由でWindows SDKを入れ直すとIncludeフォルダごと消えてしまうような動きがあり、やはり「既にある」と判断されて展開が飛ばされたと見ています。土台にゴーストが残ったままでは、表面を入れ直しても直らなかったのです。

## 決め手はレジストリの3つのキーだった

最後に効いたのはゴーストの本体であるレジストリのキーを物理的に消すことでした。消したのは3つです。WOW6432Node側のアンインストールのキー「{c0b93b80-d0a4-47fc-a4d1-21a4008a63ca}」と、Classes\Installer\Productsの下にあったSDK AddOnのキー「F7C14951D018FD14C8A5D8400972A7BF」と、WPTのキー「FF274DD83E38AFF4B179FF2830969095」です。管理者権限でも消せないキーがあり、その場合はキーの所有者をAdministratorsへ変えてから削除したのです。

その直後にwinsdksetup.exe（10.0.26100.8249）を再実行すると、IncludeとLibとbinが100%物理展開されました。確認は二つです。Includeのucrtフォルダの中にfloat.hが実在することと、Visual Studio 2022で新規のC++コンソールアプリのビルドが通ること。2026年5月10日、記録には「100%修復完了」と残しました。

## 直したあとの話

話には続きがあります。2026年6月にはctype.hの欠損が再発しました。修復やSDKの入れ直しでは解消されず、最終的にはVS2026を残したままの構成で環境を作り直して、VS2022は直って2026と共存するようになりました。

そして今も私はなんとなく2022のほうを使い続けています。直すのにあれだけ手間をかけた環境ですし、手が覚えているほうに寄るのは自然なことかもしれません。この記事がインストーラーの「成功しました」を信じて足踏みしている誰かの実物を見に行くきっかけになれば嬉しいです。
